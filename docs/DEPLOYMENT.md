# 部署规划

## 1. 策略
Companion Core 优先部署在独立新服务器或隔离环境，不与当前 DSH 生产实例共享升级周期。P0 完成前不执行生产安装。

## 2. 建议规格
正式起步建议 Ubuntu 24.04 LTS、4 vCPU、8 GB RAM、100 GB NVMe，无需 GPU，模型使用云端 API。2 GB RAM 可用于轻量验证或继续运行现有 DSH，不建议同时承担完整数据库、Worker、向量检索和浏览器自动化负载。最终按并发和数据量调整。

## 3. 初始组件
- Companion Core API
- Worker（初期可与 Scheduler 同进程）
- PostgreSQL
- 按网络结构配置反向代理和 TLS

暂不默认部署 Redis、独立向量数据库或 Kubernetes。语义检索优先评估 PostgreSQL + pgvector；吞吐确有瓶颈再加独立队列。

## 4. Docker Compose 要求
P1 实施时再创建 compose 文件。固定镜像版本；数据库持久化；尽可能非 root 运行；健康检查和资源限制；仅暴露必要端口；密钥通过服务器环境文件或 Secret 管理；日志轮转。

## 5. 备份恢复
数据库每日备份、每周完整备份和异地副本；DSH 配置及插件在变更前备份；备份加密并限制访问；定期恢复演练；根据业务重要性设定 RPO/RTO。

## 6. 网络安全
API 使用 TLS；管理接口限制可信网络并认证；数据库不暴露公网；外部模型和工具配置超时、重试上限和成本限制；监控磁盘、内存、连接数、任务积压和错误率。

## 7. 发布流程
备份数据库和配置；测试环境迁移和集成测试；固定版本发布；健康检查与消息链路验收；观察延迟和错误率；异常时关闭新功能或回滚。
