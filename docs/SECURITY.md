# 安全、隐私与审批基线

## 1. 原则
最小权限、默认拒绝、服务端权限前置、敏感操作可审计、关键变更可恢复。

## 2. 密钥与配置
禁止提交钉钉凭据、模型 API Key、数据库密码、SSH 私钥、Cookie、生产环境变量、完整配置、真实环境报告、数据库、用户消息和备份。仓库只提供不含真实值的示例配置。服务器密钥文件应限制权限并建立轮换流程。

## 3. 身份与数据隔离
平台身份由可信事件和服务端映射解析；不信任客户端自报 owner_id、group_id、role 或 scope。群 A、群 B 和主人私聊严格隔离。群聊仅保存必要共同信息。运维权限与产品内容读取权限分离。

## 4. 工具和 Computer
- L0：纯计算/本地只读。
- L1：受限网页只读。
- L2：可逆写操作，需明确授权。
- L3：资金、账号、隐私、不可逆或对外发布操作，逐次确认或禁止自动化。

浏览器使用独立账号和隔离环境；不记录 Cookie/密码；技能不得默认访问宿主机文件、任意网络或环境变量。

## 5. 成长审批
自动学习可形成记忆和技能草稿。技能必须声明权限、依赖、输入输出和副作用；沙箱测试通过前不能发布。权限、插件、人格、DSH、数据库和核心环境变更必须主人批准。发布技能保留版本和回滚路径。

## 6. 审计事件
记录身份绑定、记忆读取/导出/修订/删除、群权限变更、主动消息、外部工具副作用、技能测试/审批/发布/回滚及环境变更。日志避免保存完整敏感正文，并设置保留期限。

## 7. 事件响应
发现密钥泄露或越权时，先撤销/轮换凭据并暂停受影响工具；保留必要审计证据；判断影响范围；修复后执行权限回归测试和恢复演练。
