# P0 环境审计与验收清单

## 目标
在不改变当前 DSH 生产行为的前提下确认真实环境、插件版本、消息链路和可恢复性。P0 通过前不升级 DSH、不替换钉钉插件、不迁移数据。

## A. 环境
- [ ] OS、版本、架构、运行用户
- [ ] DSH 完整版本、安装来源、可执行文件路径
- [ ] Node/npm/pnpm 版本
- [ ] DSH_HOME、Profile、配置目录
- [ ] 启动方式（systemd / Docker / PM2 / 手动）
- [ ] 运行进程和启动参数（分享前脱敏）
- [ ] 磁盘、内存和资源使用情况

## B. 插件
- [ ] dsh-persona-dafeiyu 版本、目录、来源和依赖
- [ ] 独立钉钉插件准确名称、版本、仓库和入口
- [ ] 入站、出站和主动发送机制
- [ ] 自定义补丁或本地修改
- [ ] 图片、文件、群聊、@、引用等现有能力

## C. 配置与数据位置
- [ ] Profile 配置和 DSH_HOME
- [ ] 人格插件、钉钉插件目录
- [ ] 密钥和环境变量存储位置（只记录位置，不复制值）
- [ ] 日志和数据库位置

## D. 备份
- [ ] 备份 DSH 配置和必要运行数据
- [ ] 备份人格插件及本地修改
- [ ] 备份钉钉插件及必要配置
- [ ] 限制备份文件权限
- [ ] 生成 SHA256 校验值
- [ ] 验证备份可读取/恢复
- [ ] 明确恢复命令和回滚步骤

备份可能包含密钥和用户消息，必须加密或严格限制权限；不得上传 GitHub 或贴入聊天。

## E. 消息链路
- [ ] 主人私聊收发正常
- [ ] 群聊收发正常
- [ ] @ 机器人正常
- [ ] 图片/文件正常（若当前支持）
- [ ] 主动发送正常（若当前支持）
- [ ] 记录测试时间和结果
- [ ] 确认禁用未来 bridge 后可恢复原始行为

## F. 兼容性
- [ ] 找到 DSH 0.2.x 实际可用的事件接口
- [ ] 确认事件字段和生命周期
- [ ] 确认插件加载/卸载方式
- [ ] bridge 不重复处理或回复
- [ ] Core 故障时可降级
- [ ] 对 Tobs、dsh-channels 等候选核实版本支持，不直接安装试错

## G. 仓库
- [x] 创建私有仓库 jinke666/dafeiyu
- [x] 提交项目方案文档和基础 .gitignore
- [ ] 确认无密钥、环境报告、备份或用户数据
- [ ] 脱敏 P0 报告由主人审阅
- [ ] 根据真实环境生成专用实施命令

## P0 通过条件
版本/路径已确认；备份覆盖关键配置和插件且校验通过；消息链路基线记录完整；集成接口有证据；生产环境无非预期变更。

## 回传材料
可提供脱敏后的 environment-report.txt、compatibility-report.txt、操作系统和部署方式、钉钉插件仓库或准确名称。不要回传 API Key、AppSecret、Token、Cookie、SSH 私钥、完整生产配置或含敏感消息的备份。公网 IP、用户名和内部域名也可打码。
