# 开发路线图

以下为业余开发量级粗估，实际取决于 P0 审计和集成难度。

## P0 — 环境审计与兼容验证（约 2–4 天）
盘点 DSH、Node、插件、Profile、服务管理；备份并校验；记录消息基线；核实事件接口和第三方项目版本。验收：报告完整、备份可验证、旧系统未变更。

## P1 — Core 与身份映射（约 4–7 天）
建立 TypeScript 服务骨架和 PostgreSQL；实现健康检查、日志、用户/平台账号/群组/会话映射；实现事件幂等和最小 bridge PoC；增加降级开关。验收：测试环境私聊/群聊往返，关闭 Core 后原链路仍工作。

## P2 — 长期记忆与权限（约 5–10 天）
建立消息和记忆模型；实现候选提取、人工纠错、来源追溯、ACL 前置过滤、群隔离测试和上下文预算；评估 pgvector/Mem0。验收：权限测试通过、来源可追溯、重启后数据完整。

## P3 — Research 与 Planning（约 5–10 天）
建立研究任务和证据结构；实现多来源核验与引用；计划结构化为目标、步骤、依赖、时间、成本、风险和验收；任务可暂停、恢复。验收：研究结论有来源，计划可执行。

## P4 — 主动行为（约 4–7 天）
实现时间/事件触发、免打扰、频率限制、退避、任务跟进和审计。验收：夜间不触发、达到上限停止、主人可暂停。

## P5 — 受控成长与 Computer（约 7–14 天）
技能登记、版本、权限声明、沙箱测试、人工审批；Playwright 浏览器能力先只读后有限写操作；高风险动作确认、审计和回滚。验收：未经批准不能发布技能，越权操作被阻止。

## 里程碑原则
每阶段先在测试环境验收；阶段可独立关闭；先做好权限和任务可靠性，再追求复杂多 Agent；不为“Agent 感”过早堆框架。
