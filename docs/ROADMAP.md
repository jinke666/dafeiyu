# 开发路线图

以下为业余开发量级粗估，实际取决于 P0 审计和集成难度。新增的供应商隔离工作前置，避免未来官方 Runtime 出现时返工。

## P0 — 环境审计与兼容验证（约 2–4 天）
盘点 DSH、Node、插件、Profile、服务管理；备份并校验；记录消息基线；核实事件接口和第三方项目版本。验收：报告完整、备份可验证、旧系统未变更。

## P1 — Core 契约与身份映射（约 5–8 天）
建立 TypeScript 服务骨架、Runtime Port、Channel Adapter contract、Tool Provider contract 和 PostgreSQL；实现健康检查、日志、用户/平台账号/群组/会话映射、事件幂等和最小 bridge PoC；增加降级开关。验收：私聊/群聊往返；关闭 Core 后原链路仍工作；更换 Runtime 不改变核心数据 schema。

## P2 — 长期记忆与权限（约 5–10 天）
建立消息和记忆模型；实现候选提取、人工纠错、来源追溯、ACL 前置过滤、群隔离测试、上下文预算和供应商无关 JSONL 导入/导出；评估 pgvector/Mem0。验收：权限测试通过、来源可追溯、空环境可重建、重启后数据完整。

## P3 — Research 与 Planning（约 5–10 天）
研究支持问题拆解、来源收集、交叉验证和引用；计划包含步骤、依赖、时间、风险和验收；通过 Agent Runtime Port 执行，长任务持久化且可恢复。验收：研究结论有来源，计划可执行；任务状态由 Core 持有。

## P4 — 主动行为（约 4–7 天）
实现 Trigger/Policy/Observe、时间/事件触发、免打扰、频率限制、退避、任务跟进和审计。验收：默认 Observe、不越权；夜间不触发；达到上限停止；主人可暂停。

## P5 — 受控成长与 Computer（约 7–14 天）
技能登记、版本、权限声明、沙箱测试、人工审批；Playwright 浏览器能力先只读后有限写操作；高风险动作确认、审计和回滚。验收：未经批准不能发布技能，越权操作被阻止。

## P6 — 官方 Runtime 兼容与迁移（官方产品成熟后启动）
评估官方 API/SDK、能力覆盖、数据导出、权限、审计和部署条件；实现独立 adapter；影子测试；按只读研究、规划、主动提醒、工具操作、Computer 写操作逐级灰度；保留按任务类型回滚。不得双重执行副作用任务。

## 里程碑原则
每阶段先在测试环境验收；阶段可独立关闭；先做好权限、数据所有权和任务可靠性，再追求复杂多 Agent；不为“Agent 感”过早堆框架。Runtime 可换，Core 数据不换。
