# 长期记忆与权限设计

## 1. 目标
记忆不是把所有聊天塞进提示词，而是分离原始事件、长期事实和当前上下文。每条记忆都要知道来源、归属、可见范围和有效状态。

## 2. 分类
| 类型 | 内容 | 默认范围 |
|---|---|---|
| Core | 人格与稳定原则 | 系统内部 |
| Personal | 主人偏好、目标、约定 | 主人私聊 |
| Experience | 已完成事件和经验 | 按来源授权 |
| Group | 群内共同事实、决策、待办 | 对应群 |
| Project | 项目背景和决策 | 项目成员/主人授权 |
| Temporary | 短期上下文 | 指定会话 |
| Skill | 技能说明和经验 | 运行策略授权 |

## 3. 权限模型
每条记忆至少记录 owner_subject、scope_type、scope_id、visibility、source_message_id、created_at、updated_at、expires_at、confidence、status、version。

**先做 ACL 过滤，再做关键词或向量检索。** 不允许先召回全库再依靠提示词要求模型忽略无权内容。

| 请求主体 | Personal | 群 A | 群 B | 授权项目 |
|---|---:|---:|---:|---:|
| 主人私聊 | 是 | 共享部分 | 共享部分 | 是 |
| 群 A | 否 | 是 | 否 | 按授权 |
| 群 B | 否 | 否 | 是 | 按授权 |
| 未绑定用户 | 否 | 公开部分 | 公开部分 | 否 |

群成员个人信息即使出现在群聊，也不能自动升级为全局个人记忆。群共享记忆仅抽取群内共同事实、公开决策和待办。

## 4. 提取流程
原始消息受控保存并保留平台 ID；异步提取候选记忆；分类、归一、敏感性检查和去重；根据来源会话确定默认范围；低置信度或冲突候选待确认；保存来源和版本。群聊提取使用白名单规则，不默认跨会话保存成员私人细节。

## 5. 上下文组装
每轮只加载人格、安全规则、当前用户稳定资料（确有需要时）、近期消息、ACL 允许的相关记忆和当前任务状态。原始历史不应每轮完整注入。

初始预算可作为调优起点：人格约 500–800 tokens；核心资料约 200–400；相关记忆约 500–1,500；近期对话约 1,000–2,000。实际以命中率、纠错率、Token 成本和任务效果调优。

## 6. 冲突与生命周期
保留事实版本和来源，不静默覆盖；冲突标记后必要时询问主人；临时记忆设置 TTL；用户纠错优先于模型推断；删除/导出请求应能追踪来源、衍生记忆和索引。检索结果应携带来源摘要和时间。

## 7. 建议数据表
memories、memory_sources、memory_versions、memory_embeddings、messages、groups、group_members、audit_logs。

## 8. Mem0 边界
Mem0 可评估为抽取/检索组件，但不能替代自有 scope、ACL、来源和删除机制。若采用，必须通过适配层映射权限并通过越权测试；P0/P1 不设为强制依赖。

## 9. 必测用例
群 A 无法检索群 B；群聊无法读取主人私聊；主人仅读取群共享记忆；伪造 user_id 无法访问他人数据；冲突可追溯；删除来源后衍生记忆和索引有明确处理状态。
