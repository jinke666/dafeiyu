# 大肥鱼产品需求文档（PRD）

状态：Draft / P0

## 1. 产品愿景
大肥鱼是一个持续了解主人、记住重要事情、能主动推进任务的数字伙伴。既能自然聊天，也能围绕目标开展研究、规划和受控执行。对外保持一个统一人格，内部能力模块化。

## 2. 用户与场景
- 主人：拥有个人资料、私聊记忆、任务和全局管理权限。
- 群成员：仅访问当前群被允许共享的信息。
- 运维管理员：负责部署与恢复，不因此自动获得读取所有私聊内容的产品权限。

核心场景：日常聊天、长期记忆、群聊协作、研究、计划、主动提醒、网页操作、技能成长。

## 3. 分阶段需求
### P0 环境与安全基线
盘点 DSH、Node、插件、配置、进程和部署方式；备份 DSH、人格插件、钉钉插件及必要配置；记录消息收发基线；不升级、不迁移、不覆盖现有服务。

### P1 Core 与身份
建立独立 API 和数据库；映射平台用户、会话和群组；支持事件幂等、重试和死信；Core 不可用时原聊天链路可降级。

### P2 长期记忆
支持个人、经历、项目、群共享、临时和技能记忆；记录来源、范围、置信度、时间和状态；支持去重、冲突、修订、过期和删除；检索前先执行权限过滤。

### P3 Research 与 Planning
研究支持问题拆解、来源收集、交叉验证和引用；计划包含步骤、依赖、时间、风险和验收；长任务持久化并可恢复；不伪造来源或进度。

### P4 主动行为
支持提醒、任务跟进和约定回访；可配置允许时段、免打扰、频率和暂停；未回复时降低频率；主动消息说明真实触发原因。

### P5 受控成长与 Computer
自动形成经验和技能草稿；技能在隔离环境测试，具备版本、权限声明和回滚；浏览器操作需授权、日志和高风险确认；核心环境变更必须审批。

## 4. 非功能需求
可用性：增强服务故障不阻断原聊天。可靠性：事件幂等、持久化任务、重试和恢复。安全性：最小权限、密钥隔离、审计和备份。隐私性：个人、群聊和项目记忆边界清晰。可维护性：依赖少而成熟。成本：按需加载记忆并统计 Token。可观测性：记录请求 ID、状态、耗时和错误。

## 5. 不可妥协的记忆规则
| 场景 | 可访问内容 |
|---|---|
| 主人私聊 | 个人记忆、获授权的群共享记忆、项目记忆 |
| 群 A | 群 A 共享记忆 |
| 群 B | 群 B 共享记忆 |
| 群 A 查询群 B | 默认拒绝 |
| 群聊查询主人私聊 | 默认拒绝 |
| 主人查询群聊 | 仅群共享内容及授权内容 |

群成员个人信息不会因出现在群里就自动变成全局记忆。

## 6. 验收原则
每阶段测试正常、异常、越权和重启恢复场景。不能以模型回答看似正确替代权限与持久化测试。P0 未完成前，不对生产环境进行有写入影响的开发。
